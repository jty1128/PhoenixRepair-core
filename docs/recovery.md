# 方法恢复与复现

入口仍是 `bash run_single.sh`、`bash run_tts.sh`、`bash our_method.sh`（另有同义入口 `run_our_method.sh`）。恢复不添加新的解题策略，也不读取评测分数、隐藏测试或参考补丁。P0 包含完整策略定位和首次 patch 生成，在 P1 之前结束。

## 模型与方法边界

| 恢复相关设置 | GLM-5.2 | Qwen-3.7 Plus | Kimi K2.7 Code |
| --- | --- | --- | --- |
| Patch 单次 API 超时 | 240 秒 | 600 秒 | 240 秒 |
| Patch 输出上限（当前默认） | 32,768 | 32,768 | 32,768 |
| Thinking | 关闭 | 关闭 | 开启，回传 reasoning |
| TTS 生成/收尾时间 | 7,140 + 60 秒 | 7,140 + 60 秒 | 3,000 + 最多 60 秒 |
| TTS summary | 每轮 5 次传输，最多 3 轮 | 每轮 5 次传输，最多 3 轮 | 每轮 3 次传输；耗尽即停止；格式最多 3 轮 |
| P0 summary | 一次调用，连接/读取 30/240 秒 | 一次调用，连接/读取 30/600 秒 | 无对应历史 P0 profile |

GLM/Qwen 共用基础设施恢复代码。模型差异由 `phoenix/recovery_profiles.py` 和 `phoenix/settings.py` 指定。`main` 与 `reproduce/glm-5.2` 同步当前 GLM 200-call / 32K 版本；`configs/models/` 提供显式模型配置，其中 GLM single/TTS 保留历史 8,192 输出设定。Kimi 的 P0 配置仍明确拒绝运行。

## 哪些失败会恢复

| 情况 | 行为与上限 |
| --- | --- |
| 定位源码导出失败 | 最多 3 次尝试；不调用模型；镜像必须已在本机 |
| 生成镜像暂不可用 | 最多 3 次重试；固定 digest，禁止自动拉取不同镜像 |
| 生成环境未启动 | P0 最多 3 次重试；Single/TTS 最多 1 次重试；尚未调用模型 |
| 独立 Python 运行时不兼容 | 一次兼容修复和一次重试 |
| 容器运行时会话损坏或 PID 资源耗尽 | 每类最多一次恢复；保存当前 diff，带着历史轨迹、已用调用数、步数及执行时限继续 |
| 模型 API 超时、连接中断、HTTP 408/429/5xx | 同一请求原地重试：P0 最多 8 次尝试（含首次），Single/TTS 最多 20 次；耗尽后最多一次携带代码和轨迹的阶段恢复，保留全部已用预算 |
| 模型 API 认证、参数、证书错误，或传输恢复耗尽 | 标记 `exit_api` 并保存未完成代码及轨迹，不调用提交/审查，不发布为完成的 P0；快照失败时保留原容器 |
| 主控制器中断 | `--resume` 接管原 worker；进程 PID、启动时间、任务标签必须匹配 |
| Worker 异常消失 | 最多一次基础设施恢复；已发出但未知的请求不退回预算 |
| 提交失败、需要规范化 diff 或排除测试 hunks | 新容器重放原补丁，核验文件内容/模式，最多两次零模型调用的重放尝试 |
| 达到生成总时限 | 停止新请求和操作，保存当前补丁，再清理本次容器；不获得新生成时限 |
| 格式错误、普通测试命令超时、模型动作循环、预算耗尽 | 沿用原 agent 内部处理，不伪装成环境故障无限重开 |

退避最多 300 秒；重试记录在原阶段，`--resume` 不重置次数。外层阶段最多 12 次尝试，提交重放另受两次上限约束。重放仍失败、无可恢复补丁或预算已耗尽时，报告失败并保留材料，不把失败题从任务集合中删除。

TTS summary 的传输与格式次数也持久化。收到并保存过的响应可以直接解析；未知结果仍算一次请求。P0 summary 总共只有一次调用，若该请求没有可恢复响应，final 阶段保持阻塞；不能用“恢复”暗中增加一次付费总结。

## 预算为什么不能重置

TTS 的 sample-1、sample-2、sample-3、final 各有独立的 200 步。恢复 sample-2 时只使用 sample-2 的剩余步数和剩余时间，其他已完成阶段按补丁哈希复用。框架每次 query 的内部传输尝试和轨迹步数是不同计数，原内部重试参数不变。

P0 定位另有 150 步上限。当前 GLM 默认将 200 次调用全部用于生成：单候选最多 200 次；多候选共享 100 次，summary 占一次，final 至少 99 次并继承上游节省的额度。通过 `p0_call_budget: 160` 可选择历史 160 次 author 配额，保留原 40 次未执行的审查预算；恢复本身不会改变这项配置。每次内部请求尝试（包括失败和重试）发出前持久化计数。当前 200 次配置已用 100 次时最多再用 100 次；历史 160 次配置最多再用 60 次。最后一次额度若耗在失败请求上，仍标记 API 中断，不转成正常预算提交。验证和重放已保存补丁不增加模型调用。

瞬时 API 故障在同一轮请求内重试，保留原消息和当前容器。重试耗尽时，`generate/<author>/api-interrupted.patch` 保存包括未跟踪文件在内的工作区差异，原 Git 暂存区不变；相邻 JSON 保存错误类型及补丁哈希，轨迹保留未完成状态。主执行器的后续阶段恢复使用这些文件或容器快照，并校验哈希。请求凭据和服务商错误消息不写入中断元数据。旧版带 reviewer 的流程同步使用中断保护，失败 author 不占用预留的审查调用。

生成时限也按已消耗时间续接。零模型调用的提交重放有独立且有界的基础设施收尾时限（默认每次 600 秒），记录为恢复尝试，不算作新生成额度。控制器离线时，worker 自身的截止时间保护仍会停止新模型请求，并停止容器命令、尝试保存 diff。

## 已完成结果和工作目录

`--resume` 要求同一任务清单、issue、base commit、模型、方法、API 地址、定位输入、运行时、Docker daemon、调用预算、输出上限及上下文配置。可调整题目并发数及 I/O 准入设置。已完成的生成阶段验证 `final.patch` 哈希；summary 验证文本哈希；定位验证候选哈希。输入或已完成产物变化时拒绝复用。

定位每轮保留请求、响应和工具状态。控制器在工具执行后但检查点写入前退出时，从前一已提交状态重放已保存响应，不重新问模型、不重复叠加工具状态。源码只读，恢复过程同样没有 patch/test 工具。

生成阶段的 `attempts/` 保留原始配置、轨迹、预算和补丁；`execution.json` 保存累计消耗与恢复次数。容器丢失时只能恢复已验证的代码差异和轨迹；后台进程、临时环境变量及未进入 diff 的忽略文件不承诺复原，模型会收到通用基础设施恢复说明，先检查当前状态。工作目录及历史查询中不注入任务答案。

提交重放先在相同 base checkout 应用原 diff，再用独立 Git index 核对重放后的 tree。支持二进制文件、符号链接及文件模式。只有测试文件混入时才尝试排除测试 hunks，并要求生产代码 diff 字节一致。跨测试/生产边界的 rename、只改测试的补丁、不能匹配原 checkout 的补丁会被拒绝；原稿保留，不按测试成绩改写生产实现。

## 调度与配置

默认固定题目并发，容器准备同时最多 2 个，命令同时最多 4 个。配置可以设置：

```yaml
concurrency: 12
environment_start_concurrency: 2
local_command_concurrency: 4
adaptive_io: true
io_device: YOUR_BLOCK_DEVICE
pin_cpus: false
submission_recovery_timeout: 600
```

启用自适应时，沿用历史磁盘等待、队列深度、CPU 和内存阈值，持续高压时减少新任务及命令准入；已有 worker 不因降低并发被杀。最长稳定恢复窗口为 10 分钟。`io_device` 必须是承载实验 I/O 的 Linux 块设备名，需按自己的服务器填写。资源策略写入 `resource_policy.json`。

如果容器需要代理，可在本机环境设置 `PHOENIX_CONTAINER_PROXY`；凭据通过环境继承，不写入仓库、worker 请求或 Docker 命令行参数。不会携带原服务器账号、代理地址、sudo 密码或模型密钥。`PHOENIX_ACCOUNT_ID` 可用于共享请求节流身份；不设置时用密钥的不可逆摘要标识，不保存密钥本身。

## 验证

```bash
# 离线测试，不调用模型。
python -m pytest -q

# 使用已缓存的合成测试基础镜像，以及本机准备的工具运行时。
PHOENIX_SMOKE_BASE_IMAGE=YOUR_CACHED_IMAGE \
PHOENIX_SMOKE_RUNTIME=/path/to/portable-runtime \
python -m pytest tests/test_docker.py tests/test_recovery_docker.py -q
```

测试覆盖 GLM/Qwen 的真实容器定位→编辑→P0、故障后历史/diff/预算恢复、测试 hunks 清理、三个模型的超时提取、控制器离线时的 worker 截止保护；也覆盖未知 API 请求计费、summary 恢复、定位工具重放、PID 复用保护、不可用补丁和重试耗尽。

当前源码将 P0 单次 query 的尝试上限设为 8 次，并修正失败请求的计数和中断行为。离线测试覆盖第八次成功、重试耗尽、预算最后一次请求失败、共享调用预算、恢复后的计数和新参数入口。

来源为项目内保存的完整策略定位快照、P0 提交恢复控制器、GLM/Qwen TTS 启动器和 Kimi 运行时；公开版本将机器专用路径/标签改成运行配置，并加入持久化状态与所有权校验。后续监督/P1、官方评测器、原始定位/轨迹和任务答案不属于这些方法入口，也未移植进公开仓库。

复用已有的同模型定位需通过 `--locations` 提供；默认入口重新定位。当前 GLM 参数为 200 次共享调用、32,768 输出、4 并发。Kimi single/TTS 配置保留 3,000 秒生成时限，不支持 P0。数据、成绩、用量统计、原始定位和轨迹均不纳入仓库提交。
